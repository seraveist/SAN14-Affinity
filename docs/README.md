# 삼국지14 친애 편성기

정적 웹 앱입니다. `index.html`을 브라우저에서 열면 바로 실행됩니다.

## 고정된 로직

- 친애 관계는 `☆`, `◎`, `○`만 사용하고 `X`는 제외합니다.
- 버프 중첩은 같은 집단 안의 양방향/단방향 친애 연결 수로 계산합니다.
- 장수 점수는 `max(통솔+무력, 통솔+지력) + 개성점수`를 우선값으로 사용합니다.
- 개성 점수는 금색 `+5`, 파란색 `+2`, 빨간색 `+0`입니다.
- `악주`, `응원`은 추가 `+1`을 더합니다.
- 보유 장수 편성은 v1.2 코어 중심 로직으로, 먼저 코어무장을 고른 뒤 핵심/상위/보조 무장을 순서대로 배정합니다.
- 의형제/결혼 추천은 v1.2 편성 결과를 기준으로 보완 후보를 계산합니다.
- 보유 장수 입력은 쉼표, 공백, 줄바꿈으로 구분할 수 있습니다.
- `집단 상한`은 기본값 20명, 입력 상한 30명입니다.
- 목표 집단 수는 전체 보유 장수를 강제로 수용하기 위한 값이 아니라, 만들고 싶은 코어 집단 수로 사용합니다.
- 보유풀 안에 친애 연결이 전혀 없거나 코어 집단에서 충분한 배정 점수를 얻지 못한 장수는 기본 편성에서 `미편성`으로 남깁니다.
- `코어 고정`에 입력한 보유 장수는 자동 코어 선정 전에 먼저 코어로 고정합니다.
- 코어 고정 수가 목표 집단 수보다 많으면 목표 집단 수를 고정 코어 수까지 보정합니다.
- 보유 장수 목록에 동명이인이 일부만 입력되면 `동명이인 선택` 프레임에서 후보를 직접 고릅니다.
- 동명이인 이름이 후보 수만큼 입력되면 모든 후보가 존재한다고 보고 `장소(1)`, `장소(2)`처럼 구분합니다.
- 코어 후보는 친애 폭, 통솔/무력/지력, 개성 점수, 전투 독립성, 기존 코어와의 중복도를 함께 봅니다.
- 보좌/응원/악주 보유자는 기본적으로 보조무장으로 보되, 주유처럼 90급 능력치를 가진 최상위 장수는 코어 후보에 남깁니다.
- 목표 집단 수가 적을 때는 친애 폭만 넓은 참모/실무형 앵커보다 전투형/90급 핵심 코어를 우선합니다.
- 4번째 코어부터는 아직 선택된 코어들이 커버하지 못하는 2~4인 라인의 대표성을 강하게 반영합니다.
- 이미 선택된 코어와 강하게 이어진 후보는 독립 라인이 약하면 코어 선정에서 보류하고 기존 집단 흡수를 우선합니다.
- 참모/실무형 앵커라도 보호 가능한 3인 이상 라인을 살리고 미편성을 줄이는 효과가 크면 코어 후보로 다시 허용합니다.
- 라인 대표 코어가 선택되면 해당 라인의 강한 친애 구성원은 먼저 보호 배정합니다.
- 코어별 집단에는 핵심무장, 상위무장, 보조무장, 예비무장 순서로 친애 연결이 있는 장수만 배정합니다.
- 개별 배정 뒤에도 남은 2~3인 친애 라인은, 특정 코어 집단과 연결이 있으면 패키지 단위로 추가 배정합니다.
- 집단 간 밸런스 검증 단계에서는 현재 집단보다 다른 코어 집단과 연결이 뚜렷하게 강한 장수를 이동시킵니다.
- 큰 집단에 붙은 2~3인 추종 패키지가 작은 집단의 코어와도 잘 맞고 총점 손실이 작으면 패키지 단위로 재배치합니다.
- KEY/UPPER급 배정 이후에는 비-별 2~3인 패키지가 더 작은 집단의 내부 라인에 잘 붙는지 재검증합니다.
- 친애 연결이 없거나 코어 집단에서 충분한 배정 점수를 얻지 못한 장수는 기본 편성에서 `미편성`으로 남깁니다.
- 미편성 장수는 `후보 라인`, `강력 단독`, `보조 후보`, `일반 미편성`으로 다시 분류해 표시합니다.
- 재배치 과정은 별도 안내 없이 최종 편성 결과에만 반영합니다.
- 결과창은 `편성 결과`와 `의형제/결혼 추천` 탭으로 나뉩니다.
- `편성 결과` 탭은 집단 구성과 연결 근거만 표시합니다.
- 무장 배지는 `관우 +2`처럼 이름과 버프점수만 표시합니다.
- 연결 근거는 작은 카드로 표시하고, 첫 번째 기준 장수 순서대로 정렬합니다.
- `의형제/결혼 추천`은 총점 상승이 아니라 편성 보정 효과를 기준으로 계산합니다.
- 추천 우선순위는 `소규모 라인 병합`, `강력 단독 투입`, `역할 부족 보정` 순서입니다.
- 단독 장수와 역할 보정 평가는 `통솔 > 무력/지력 > 정치` 순서로 보고, 매력은 편성 우선도에서 제외합니다.
- 기본 편성의 `미편성` 장수는 추천 탭에서 `미편성 구제` 후보로 우선 검토합니다.
- 미편성 추천은 분류 결과를 직접 사용해 `후보 라인`은 병합, `강력 단독`은 투입, `보조 후보`는 보강 후보로 계산합니다.
- 여무장은 기본적으로 기혼 상태로 보고, 결혼 추천은 `미혼 가정` 후보로 별도 표시합니다.
- 결혼 추천은 같은 기준을 따르되, 같은 목적이면 의형제보다 뒤에 정렬합니다.
- 보유 장수 안의 여무장 중 `응원`/`악주` 보강 후보는 `범위 버프 보강`으로 검토합니다.
- 추천 탭은 `의형제`, `결혼`, `미편성 구제`, `응원/악주 보강` 필터로 결과를 좁힐 수 있습니다.
- 이미 `☆` 관계인 장수 조합은 의형제/결혼 추천에서 제외합니다.
- 추천 예상 편성이 v1.2 기본 분파의 별 라인을 깨면 제외하고, 쌍원/핵심 코어 라인을 크게 흔들면 분파 안정성 감점을 적용합니다.
- 같은 목적의 후보가 여러 개면 친애 폭이 더 넓은 앵커 장수를 우선합니다.
- 추천의 예상 변화는 실제 변동이 있는 항목만 배지로 표시하고, 예상 편성은 카드형 목록으로 표시합니다.
- 중심 분석은 결과 탭을 표시하지 않고, 중심 장수가 친애하는 대상과 중심 장수를 친애하는 대상을 합친 전체 직접 친애 목록을 표시합니다.
- 중심 분석의 3인 이상 경로는 점수가 높은 순서로 최대 50개를 `집단 추천` 스크롤 프레임에 표시하며 탐색 단위는 `단계`로 표기합니다.
- 집단 카드 안의 단순 의형제 후보 목록은 표시하지 않습니다.
- 구현 소스는 v1.2 코어 중심 편성 흐름을 메인 로직으로 유지하며, 이전 버전의 별 컴포넌트 우선 편성/소집단 교환 재배치 코드는 제거했습니다.
- 회귀 테스트 샘플은 `조조계`, `유비계`, `손권계`, `원소계` 4개로 고정합니다.
- 동명이인 표기는 향후 별도 alias 데이터가 준비되면 `순욱(문약)`, `유표(경승)`처럼 `이름(자)` 형식으로 확장할 예정입니다.

## 데이터 갱신

원본 `affinity_index.json`과 엑셀 파일이 바뀌면 아래 스크립트로 `data.js`를 다시 생성합니다.
기본값은 저장소 루트의 `affinity_index.json`과 `삼국지14_전체무장_공유(통합본)의 사본.xlsx`입니다.

```powershell
python .\docs\build_data.py
```

## 회귀 테스트

기본 샘플 4개를 현재 로직으로 실행합니다.

```powershell
node .\docs\regression_runner.mjs
```

현재 작업트리 결과를 `HEAD` 기준 결과와 비교합니다.

```powershell
node .\docs\regression_runner.mjs --compare
```

다른 위치의 파일을 사용하려면 환경변수로 지정할 수 있습니다.

```powershell
$env:SAN14_AFFINITY_JSON = 'C:\path\to\affinity_index.json'
$env:SAN14_WORKBOOK = 'C:\path\to\삼국지14_전체무장_공유(통합본)의 사본.xlsx'
python .\docs\build_data.py
```
